A full-stack healthcare appointment booking platform built on the MERN stack (MongoDB, Express.js, React, Node.js). Patients find and book appointments with doctors, doctors manage their schedules and patient visits, and admins approve doctors and oversee the platform — all behind secure, role-based authentication. Stack: Node.js v16+ · React 18 · Express.js 4 · MongoDB (Atlas or local) · JWT auth · MIT License

Features Patients ● Register and log in securely ● Browse and search doctors by name or specialization ● View doctor profiles (experience, fees, qualifications, bio) ● Book appointments by date and time slot, with double-booking protection ● View, track, and cancel their own appointments ● Upload reports or prescriptions to an appointment Doctors ● Register with a professional profile (pending admin approval before going live) ● Manage their own profile, availability, and consultation fee ● View incoming appointments and confirm, complete, or cancel them Admins ● Approve or reject doctor applications ● View platform-wide stats (patients, doctors, appointments) ● Activate or deactivate any user account Platform ● JWT-based authentication with role-based access control (patient / doctor / admin) ● Passwords hashed with bcrypt ● Centralized error handling and request logging ● File uploads via Multer with type/size validation Tech stack Layer Technology Frontend React 18, React Router, Axios, Bootstrap 5 Backend Node.js, Express.js Database MongoDB (Atlas or local) via Mongoose Auth JSON Web Tokens (JWT), bcrypt File uploads Multer Validation express-validator Security Helmet, CORS

Getting started Prerequisites ● Node.js v16 or higher and npm ● A MongoDB instance — MongoDB Atlas (cloud) or MongoDB Community Server (local) ● Git

Clone the repository git clone cd book-a-doctor
Backend setup cd server npm install Copy the example environment file:
macOS/Linux
cp .env.example .env

Windows (PowerShell)
copy .env.example .env Fill in MONGO_URI and JWT_SECRET in .env (see Environment Variables below), then start the API: npm run dev The API runs at http://localhost:5000. You should see: MongoDB connected: Server running in development mode on port 5000 3. Frontend setup Open a new terminal window (the backend needs to keep running): cd client npm install cp .env.example .env # or: copy .env.example .env (Windows) npm start The app opens at http://localhost:3000. Windows PowerShell users: commands chained with && (e.g. cd server && npm install) don't work in default PowerShell — run each command on its own line instead, or upgrade to PowerShell 7. Environment variables server/.env Variable Description Example NODE_ENV Environment mode development PORT API port 5000 MONGO_URI MongoDB connection string mongodb://127.0.0.1:27017/book-a-doctor or an Atlas SRV URI JWT_SECRET Long random secret used to sign tokens (generate your own — never commit this) JWT_EXPIRES_IN Token lifetime 7d CLIENT_URL Frontend origin, for CORS http://localhost:3000

client/.env Variable Description Example REACT_APP_API_URL Base URL the frontend calls http://localhost:5000/api

React only reads .env at startup — restart npm start after changing it. Creating the first admin account Admins can't self-register through the sign-up form by design. Create the first one from the command line: cd server node seedAdmin.js "Admin Name" admin@example.com yourStrongPassword Then log in at http://localhost:3000/login with those credentials to reach the Admin Dashboard, where you can approve pending doctors. API reference Method Route Access Description POST /api/auth/register Public Register as a patient or doctor POST /api/auth/login Public Log in, returns a JWT GET /api/auth/me Private Get the current user's profile GET /api/doctors Public List approved doctors (search/filter) GET /api/doctors/:id Public Get a single doctor's profile GET /api/doctors/me/profile Doctor Get own doctor profile PUT /api/doctors/profile Doctor Update own doctor profile POST /api/appointments Patient Book an appointment GET /api/appointments/my Patient List own appointments GET /api/appointments/doctor Doctor List appointments for the doctor PUT /api/appointments/:id/status Doctor, Admin Confirm, complete, or cancel PUT /api/appointments/:id/cancel Patient Cancel own appointment POST /api/appointments/:id/documents Private Upload a report or prescription GET /api/admin/stats Admin Platform-wide stats GET /api/admin/doctors/pending Admin List doctors awaiting approval PUT /api/admin/doctors/:id/status Admin Approve or reject a doctor GET /api/admin/users Admin List all users PUT /api/admin/users/:id/toggle Admin Activate or deactivate a user

All private routes require an Authorization: Bearer header. Troubleshooting MongoDB connection error: querySrv ECONNREFUSED ... Node's DNS resolver on Windows sometimes fails to resolve Atlas's SRV record even though nslookup works fine. Fix by forcing a public DNS resolver at the top of server.js (and any standalone script like seedAdmin.js): const dns = require('dns'); dns.setServers(['8.8.8.8', '1.1.1.1']); MongoDB connection error: connect ECONNREFUSED 127.0.0.1:27017 No local MongoDB instance is running. Either start your local MongoDB service (Start-Service -Name MongoDB on Windows) or switch MONGO_URI to an Atlas connection string. Registration/login fails with a generic error Open the browser's dev tools → Network tab → inspect the failed request's status code and response body. Common causes: password under 6 characters, duplicate email, or the frontend and backend .env URLs not matching. "Your profile is awaiting admin approval" Expected behavior for new doctor accounts — log in as an admin and approve the doctor from the Admin Dashboard.
